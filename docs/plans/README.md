# Cutpay — an educational Paypercut clone

> Study project only. **No real money moves.** Every bank, card network, BNPL provider and wallet is a local simulator.
> Inspired by [Paypercut](https://paypercut.com/) — we use our own name ("Cutpay"), branding and design.

## Product surface we mimic

| Paypercut product | Cutpay phase |
|---|---|
| Merchant dashboard, sign-up | 0, 1 |
| Online checkout (hosted) + card payments + 3DS | 1 |
| Balances, fees, settlement, payouts | 2 |
| Developer API, sandbox/live, webhooks, embedded checkout, plugins | 3 |
| Payment links, QR codes, Virtual POS terminal | 4 |
| Billing: subscriptions, pre-auth, split payments | 5 |
| BNPL aggregator + smart routing | 6 |
| Apple Pay / Google Pay / BLIK, multi-currency, localised checkout | 7 |
| Digital onboarding / KYC, team, disputes, reports | 8 |
| Observability, resilience, plugins, load | 9 |

## Stack

- **Backend:** Java 21, Spring Boot 3.x, Gradle (Kotlin DSL) multi-module, Spring Data JPA, Flyway
- **Messaging:** Apache Kafka (KRaft), Schema Registry, Spring Kafka
- **Database:** PostgreSQL 16 — one database per service (same container locally)
- **Frontend:** React 18 + TypeScript, Vite, pnpm workspaces, TanStack Query, React Router, Tailwind + shadcn/ui, Recharts, react-i18next
- **Infra:** Docker Compose, Redis, Mailpit, Kafka UI, Prometheus, Grafana, Tempo, OpenTelemetry
- **Tests:** JUnit 5, Testcontainers, ArchUnit, Playwright, k6

## Global conventions

### Money
- Amounts are `long` **minor units** + ISO-4217 `currency` (`CHAR(3)`). Never `double`/`float`.
- Postgres: `amount BIGINT NOT NULL`, `currency CHAR(3) NOT NULL`.
- Rounding for fees: `RoundingMode.HALF_EVEN`, applied once at fee computation.
- Shared value object `Money(long minor, Currency currency)` in `libs/common-money`.

### IDs
- Public IDs are prefixed, Stripe-style: `pay_`, `re_`, `mer_`, `usr_`, `plink_`, `sub_`, `po_`, `evt_`, `whe_`, `key_`.
- Generated as prefix + ULID (sortable). Internal PK may be the same string.

### Modes
- Every merchant-owned row has `livemode BOOLEAN`. API keys `sk_test_…` / `sk_live_…` select the mode. "Live" still hits simulators — it just mimics separation.

### API
- REST, JSON, `snake_case` fields, versioned under `/v1`.
- All `POST` requests accept `Idempotency-Key` header; stored 24h (Redis + Postgres fallback).
- Errors: `{ "error": { "type", "code", "message", "param" } }`.
- Pagination: cursor-based `?limit=&starting_after=`.
- OpenAPI 3 spec generated by springdoc per service, aggregated at gateway.

### Events (Kafka)
- Topic naming: `<domain>.events` (e.g. `payment.events`), key = aggregate id (ordering per aggregate).
- Envelope: `{ event_id, event_type, occurred_at, aggregate_id, merchant_id, livemode, version, payload }`.
- Producers use the **transactional outbox** (`outbox` table + relay poller, or Debezium in phase 9).
- Consumers use an **inbox** table (`processed_events(event_id PK)`) for idempotency.
- Failures: retry topics `<topic>.retry.<n>` + DLT `<topic>.dlt` (Spring Kafka `@RetryableTopic`).
